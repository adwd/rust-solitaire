# Rust ソリティア実装計画

作成日: 2026年10月3日

状態: 2026年10月3日に合意し、macOS 初版の実装と検証を完了。同日の追加依頼で Web とネイティブの共通構成、GitHub へのプッシュ、GitHub Pages での公開を承認。さらに自動クリア、GPU の勝利演出、絵札のスートの視認性改善を追加依頼。リポジトリ名は rust-solitaire。検証結果は [VALIDATION.md](VALIDATION.md) を参照。

Rust でクロンダイクのソリティアを作る。ゲームの状態とルールを扱う画面非依存のライブラリ、GPU 描画の共通 UI、デスクトップ起動、Web 起動を Cargo workspace 内の別クレートに分ける。macOS とブラウザで同じルール・画面・操作を使って遊べることを完成条件とする。

## GUI ライブラリの選定

`egui + eframe + wgpu` を推奨する。公式構成では `eframe` がアプリの起動やウィンドウとの統合を担い、`egui-wgpu` が描画を担う。独自のカード盤面と設定用の UI を組み合わせる今回の用途に適していると判断した。[egui の構成](https://github.com/emilk/egui/blob/main/ARCHITECTURE.md)、[eframe の公式ドキュメント](https://docs.rs/eframe/latest/eframe/)

| 候補 | 今回の用途に対する判断 |
| --- | --- |
| egui + eframe + wgpu | カードの描画と当たり判定をアプリ側で定義しやすく、ボタンや設定画面も同じ UI で構築できるため採用候補とする |
| GPUI | GPU を使う Rust UI の有力な代替候補。公式には immediate と retained を組み合わせた設計とされている。GPUI 自体を使うことを優先するなら、コアの設計を保ったまま GUI クレートを `solitaire-gpui` に変更する |

GPUI の説明は [GPUI 公式サイト](https://gpui.rs/) に基づく。上表の適性評価はこのプロジェクトについての設計判断である。初版で両方の GUI を実装する計画ではない。

調査時の環境には Rust / Cargo 1.94.0 がある。依存バージョンは実装開始時に MSRV と API を確認して決め、`Cargo.lock` を管理する。`wgpu` を有効化し、実行時のレンダラーも明示して GPU バックエンドを確認する。

## 初版のゲームルール

これは初版で採用するクロンダイクのルールであり、バリエーション間の差をここで固定する。

- ジョーカーを除く52枚を使い、場札7列に1〜7枚ずつ配る。各列の最上段だけを表向きとし、残り24枚を山札にする。
- 場札は赤黒交互かつ数字が1つずつ小さくなるように重ねる。表向きの正しい連続列はまとめて移動できる。
- 場札の空き列には K、または K から始まる連続列だけを移動できる。
- 組札はスートごとの4枠とし、A から K まで昇順に1枚ずつ積む。
- 場札と捨て札の最上段から組札へ移動できる。組札の最上段から場札への戻しも、場札側の条件を満たせば許可する。
- 場札の移動で裏向きのカードが最上段に現れたら、その操作の一部として自動的に表向きにする。
- 山札から1枚または3枚を順番に捨て札へ移す。残りが3枚未満なら残り全部をめくる。捨て札から使えるのは常に最上段の1枚だけとする。
- 山札が空なら捨て札を裏返して山札へ戻せる。再シャッフルせず、再巡回の回数制限も設けない。山札と捨て札が両方空なら操作は無効とする。
- 52枚すべてが組札に移動したら勝利。手詰まりや勝利不能を断定する判定は初版には含めない。
- めくり枚数の変更は新規ゲームから適用する。同じ配札での再挑戦はシードとルールの両方を保持する。

## ワークスペース構成

以下の構成で実装する。

```text
rust-solitaire/
├── Cargo.toml                 # workspace と共有設定
├── Cargo.lock
├── README.md                  # 起動方法と操作説明
├── docs/
│   └── PLAN.md                # この計画
└── crates/
    ├── solitaire-core/
    │   ├── Cargo.toml
    │   └── src/
    │       ├── lib.rs         # 公開 API
    │       ├── card.rs        # カード、スート、ランク
    │       ├── game.rs        # 状態、配札、勝利判定
    │       ├── rules.rs       # 合法手の判定と列挙
    │       ├── action.rs      # 操作とエラー
    │       └── history.rs     # Undo / Redo
    ├── solitaire-egui/
        ├── Cargo.toml
        └── src/
            ├── lib.rs        # 共通 UI の公開 API
            ├── app.rs        # コアと GUI の接続
            ├── board.rs      # 盤面レイアウトと描画
            ├── input.rs      # 選択、ドラッグ、ショートカット
            └── theme.rs      # 配色とカードの見た目
    ├── solitaire-desktop/
    │   ├── Cargo.toml
    │   └── src/main.rs       # CLI、標準ウィンドウ、ネイティブ起動
    └── solitaire-web/
        ├── Cargo.toml
        └── src/lib.rs        # WASM、canvas、WebRunner の起動と終了
```

依存方向は両起動クレート → `solitaire-egui` → `solitaire-core` の一方向とする。コアは GUI、ウィンドウ、GPU、画面座標、入力デバイスの型に依存しない。将来の GUI 差し替えは別の利用側クレートで行えるようにし、現時点で汎用的な GUI 抽象化レイヤーは追加しない。

Web 起動は `eframe::WebRunner` と `wasm-bindgen` を使う。共通 UI の時計は `web-time`、WASM の乱数はブラウザのエントロピーを使う。ネイティブ機能と WebGPU / WebGL 機能は各起動クレートで指定し、ネイティブ版は Metal、Web 版は WebGPU と WebGL のフォールバックで描画する。HTML、CSS、JavaScript は `web/`、静的サイト生成は `scripts/build-web.sh` に置く。CI は両版を検証してから Pages へ公開する。

### コアが担当するもの

- カード、山札、捨て札、場札、組札、ルール設定、ゲーム状態。
- シードからの決定的なシャッフルと配札。実際のランダムなシードの取得はアプリ側が行う。
- 操作の検証と適用、合法手の列挙、自動的な表返し、勝利判定。
- Undo / Redo と手数。ドラッグやクリックの違いによって結果が変わらないこと。

コアの状態は外部から直接書き換えられないようにする。GUI は読み取り用 API から盤面を取得し、操作 API を通して変更する。コアはファイル I/O、システム時計、OS の乱数取得を行わず、ディスプレイも GPU もない環境でテストできる通常の Rust ライブラリとする。`no_std` 対応は初版の要件に含めない。

### 公開 API の方針

具体的な型名は実装時に調整するが、責務は次のように分ける。

| API | 用途 |
| --- | --- |
| `Game::new(seed, rules)` | 同じ条件で同じ初期盤面を生成する |
| `Game::view()` | 読み取り専用の盤面情報を取得する |
| `Game::legal_actions()` | 現在実行できる操作を取得する |
| `Game::apply(action)` | 1つの操作を検証して適用し、結果または理由付きのエラーを返す |
| `Game::undo()` / `redo()` | 状態と手数を前後に戻す |
| `Game::status()` | プレイ中または勝利を取得する |
| `Game::auto_finish_plan()` | 裏札がなく、山札巡回と組札移動だけで完走できると証明した手順を返す。元の盤面・履歴は変更しない |

操作は山札をめくる、捨て札を戻す、カードを移動する、に分ける。移動元は場札の列と開始位置、捨て札の最上段、組札の最上段を表し、移動先は場札または組札を表す。座標からこれらへの変換は GUI が行う。範囲外の指定、裏向きカード、同じ列への移動、不正な連続列などもコアで拒否する。

無効な操作は盤面、履歴、手数を一切変えない。有効な操作は自動的な表返しまで含めて1手と数え、1回の Undo で全体を戻す。新しい操作を Undo 後に適用した場合は Redo 履歴を消す。初版は52枚の状態を保存するスナップショット方式を使い、逆操作の実装漏れを避ける。

再現性は配札アルゴリズムと依存バージョンを固定した同じ実装で保証する。固定シードの既知の配札をテストし、将来アルゴリズムを変更する場合は互換性を明示する。

### GUI が担当するもの

- ウィンドウ、カードの配置と描画、マウスとキーボードの入力。
- 選択中のカード、ドラッグ位置、ホバー。ユーザーの追加指定により、選択・ドラッグ時に移動先を自動で強調しない。候補の表示は Hint を明示的に押したときだけ行う。
- コアの合法手を使った移動候補の表示とヒント。ヒントは見えている情報に基づく合法手の案内とし、解けることや最善手を保証するものにはしない。
- 新しいシードの取得、設定画面、手数と経過時間の表示。

ドラッグ中は表示用の状態だけを更新し、ドロップ時にコアへ1回だけ操作を渡す。無効な場所へのドロップはキャンセル扱いとする。プレビューと最終判定は同じコアのルールを使い、GUI に独自の合法手判定を重複実装しない。

## 画面と操作

落ち着いた濃緑の盤面に、白いカードと明確な赤黒のスートを配置する。カードは図形と文字を中心に描画する。UI はユーザーの追加指定により英語に統一する。egui の既定フォントを使い、日本語フォントを読み込まない。数字札の柄はランクに合わせたスート数にし、J・Q・K は異なる絵札で描く。上下の角はランクだけを表示し、重複した小さなスートは置かない。J・Q・K は衣装の中央に明るい背景と大きなスートの紋章を1つ置き、同じ色のスートも形で判別できるようにする。

上部に「新規ゲーム」「再挑戦」「戻す」「やり直す」「ヒント」と設定を置き、その下に山札・捨て札・組札4枠、さらに場札7列を並べる。設定から1枚／3枚めくりとシードを指定できるようにする。勝利時は結果と再プレイ操作を表示する。

- ドラッグで単体カードと連続列を移動できる。
- カードをクリックしてから移動先をクリックする方法でも操作できる。
- ダブルクリックで合法な組札へ移動できる。
- `Cmd/Ctrl+Z` で Undo、`Cmd/Ctrl+Shift+Z` で Redo、`Esc` で選択やドラッグを解除する。
- 選択中のカードは枠線で区別する。移動先の自動強調は行わない。
- ウィンドウは OS 標準のタイトルバーを使い、閉じる・最小化・拡大ボタンを有効にする。
- 初期ウィンドウはおよそ1100×800とし、リサイズと HiDPI に追従する。長い場札は重なり間隔を調整し、必要なら盤面をスクロール可能にして操作できる状態を保つ。
- 新規ゲームと再挑戦は進行中なら確認を出す。

経過時間は GUI が管理し、最初の有効な操作から自動クリアの確定（または手動の勝利）までを計測する。再挑戦と新規ゲームでリセットし、Undo では巻き戻さない。操作時は滑らかな表示を目指し、待機中はタイマー表示などに必要な頻度だけ再描画する。

## 追加依頼の自動クリアと勝利演出

裏向きの場札が残る間は自動クリアを開始しない。すべて表向きでも即座に勝利と見なさず、コアが盤面の複製で合法な組札移動・山札めくり・再巡回を試し、52枚が組札へ収まる完全な手順を証明する。3枚めくりで巡回しても進展できない盤面は対象外とする。一般的な解答探索は行わない。

証明できた瞬間に時間を止め、約55ms間隔でカードを送る。複数のカードが曲線に沿って素早く移動し、最後のカードの到着後に勝利画面を表示する。手数と履歴には自動操作も記録し、Undo は演出を中断して計測と手動操作を再開する。ブラウザの一時停止から復帰しても不可視の一括実行にならないよう、1フレームで適用する操作は1つまでとする。

勝利演出には共通 UI の wgpu カスタム描画を使う。WGSL で火花の位置・重力・色・発光を計算し、1152個の火花をインスタンス描画する。加算合成の花火と光の輪を約6.8秒間表示し、終了後は連続再描画を止める。Metal と WebGPU / WebGL で同じコードを利用し、特別な GPU 機能は要求しない。

## 初版に含めない機能

別ルールのソリティア、任意の盤面の解答ソルバー、勝てる配札の保証、スコア方式やランキング、対戦、サウンド、ゲーム保存と再開、モバイル専用の操作・画面設計は後続の拡張候補とする。

## 実装の順序

1. **構成と起動を確認する。** 合意した workspace とコア・GUI を作り、依存バージョンを確定する。最小ウィンドウで `wgpu` による起動を確認する。
2. **コアを実装する。** カード、配札、1枚／3枚めくり、すべての移動規則、勝利判定、履歴を実装し、画面なしで検証する。
3. **基本操作をつなぐ。** 盤面を描画し、クリック移動、山札操作、組札への移動でゲームが進む状態を作る。
4. **操作性を仕上げる。** 連続列のドラッグ、明示的なヒント表示、Undo / Redo、再挑戦、シード指定、勝利画面、リサイズを整える。
5. **検証と説明を完成させる。** 自動検証と macOS 上の実操作を行い、起動方法、操作方法、既知の制限を README にまとめる。
6. **承認済みの Web 拡張。** 共通 UI と両起動クレートへ分割し、WASM とブラウザの操作を検証する。公開リポジトリを作り、両版の CI と GitHub Pages 公開を設定して、公開 URL でも起動を確認する。
7. **追加依頼の仕上げ。** 自動クリアの証明、時間停止、カード移動と GPU の勝利演出を共有 UI に追加する。絵札のスートを改善し、Web と macOS の更新版を検証・公開する。

承認済みの範囲内で実装を進める。ゲーム種別や GUI ライブラリの変更など、計画の根本に関わる変更が必要な場合は理由と変更案を提示する。

## 検証と完成条件

コアではルールの境界条件と履歴の正しさを重視する。通常の単体テストに加え、複数のシードと合法手列を使うプロパティテストで状態の不変条件を確かめる。

- 52枚が重複や欠落なく存在し、初期配札の枚数と表裏が正しい。
- 場札の赤黒交互と降順、空き列の K 制限、組札のスートと昇順が守られる。
- 裏向きカード、不正な連続列、無効な添字、同じ場所への移動が状態を変えずに拒否される。
- 3枚めくりの端数、捨て札の最上段だけを使う制約、山札の再巡回時の順序が正しい。
- 移動、山札操作、再巡回、自動的な表返し、勝利を含む操作を Undo / Redo で正確に復元できる。
- Undo 後の新しい有効操作で Redo 履歴が消え、無効操作では履歴が変わらない。
- 固定シードの配札と合法手判定が再現できる。合法手の列挙と操作の受理が一致する。
- 組札が完成する直前のテスト盤面と操作列で、勝利までの流れを確認できる。

合意後に実行する基本コマンドは次のとおり。

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build --release -p solitaire-desktop
cargo run --release
cargo clippy -p solitaire-web --target wasm32-unknown-unknown --locked -- -D warnings
bash scripts/build-web.sh
```

完成には、これらのチェックに加えて macOS 上で GPU 描画、ドラッグとクリック、連続列の移動、山札の再巡回、履歴、再挑戦、勝利、リサイズを実際に確認する。重なったカードの選択、ドラッグの解除、英語とスートの表示も対象にする。GPU が必要な確認とコアだけの自動テストは分け、確認できなかった環境は明記する。

`cargo test -p solitaire-core` が GUI と GPU の依存を必要とせず実行でき、利用側から状態を直接変更できないことも完成条件とする。Windows と Linux での動作保証や配布パッケージの作成は初版の完成条件には含めない。

## 合意する内容

初版は `rust-solitaire`、クロンダイクの1枚／3枚めくり、`egui + eframe + wgpu`、独立したコアと GUI、macOS を対象として合意済み。追加依頼により、共通 UI と起動処理を4クレートに分け、Web 版を実装し、GitHub へのプッシュと GitHub Pages での公開まで進める。
